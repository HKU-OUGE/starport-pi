# 操作指引

## 專案與任務

每個選定伺服器可建立多個工作區，會話按伺服器／工作區保存。`/workspace` 建立新的空專案；重新啟動工作台會接續當前專案。模型的 `read`、`write`、`list` 都只處理 `/workspace` 內的相對路徑。

例如直接告訴模型：

> 建立一個 Python 程式，讀取 input.csv，將摘要寫入 /output/summary.json。先以 2 CPU、4 GiB、120 秒執行，查看日誌並核對結果。

`bash` 回傳任務 ID，模型用 `job_status` 和 `job_logs` 查詢。單一工作區一次只執行一個命令任務，避免兩個命令同時修改專案；不同工作區按服務總預算並行。CPU、記憶體或 GPU 不足會返回明確容量錯誤。

長程式應明確指定 `timeout`，預設 600 秒，最大 86400 秒。沒有日誌輸出不會觸發超時，關閉工作台也不會取消已開始的遠端任務。需要終止時指定任務 ID 使用 `job_cancel`；只有確認 runtime 清除後才釋放預留。

近期日誌保留 16 MiB，超量時輪替，不因日誌量殺掉計算。`job_logs` 返回 byte cursor 和 `truncated`，可增量讀取。需要永久保留的完整日誌由程式寫到 `/output`。

## 上傳、下載與資料版本

`/upload` 由操作人員選擇本機檔案與遠端相對路徑，按 1 MiB 分塊上傳，逐塊與整檔核對 SHA-256。中斷後重跑相同檔案／目標，使用既有上傳 ID 接續；完成後移除中轉內容，只保留小型收據。

`/download` 指定任務 ID、產物相對路徑及本機儲存位置。下載先寫 `.partial`，校驗完成才更名；任務執行中也可下載已落盤檔案。若檔案在讀取期間改變，返回 `artifact_changed`，應先讓程式產生穩定快照。下載不會覆蓋成未校驗的半個檔案。

模型可用 `dataset_publish` 把遠端專案資料夾發布成新的只讀資料 ID。後續 `bash` 的 `datasets` 參數指定這些 ID，即可從 `/data/shared/<id>` 讀取。修改專案不會改變已發布版本；更新時再發布。這些版本在同一個 worker 內共用，跨伺服器同步需由操作人員額外安排。

每次上傳／每個資料版本上限為 100 GiB；每個版本最多 10,000 個檔案。這不是全磁碟硬配額，部署時應給服務獨立的資料磁碟或檔案系統 quota。

## 連線恢復

- 訂閱過期：`/network` 更新訂閱，再「啟動／套用出口」。
- SSH 主機金鑰變更：在操作端核實實例，重新 `/verify-server`，不跳過主機驗證。
- 伺服器重啟／SSH 隧道中斷：確認 `/status` 後重新 `/tunnel`。斷線期間外網保持封閉。
- 返回 `remote_outcome_unknown`：先查詢任務或檔案，避免盲目重送有副作用的命令。
- `controller_interrupted`：控制程序確實消失；服務只回收該任務的 runtime。這和工作台斷線、程式暫時不輸出日誌不同。
