# 操作指引

## 项目与任务

每个选定服务器可建立多个工作区，会话按服务器／工作区保存。`/workspace` 建立新的空项目；重新启动工作台会接续当前项目。模型的 `read`、`write`、`list` 都只处理 `/workspace` 内的相对路径。

例如直接告诉模型：

> 建立一个 Python 程式，读取 input.csv，将摘要写入 /output/summary.json。先以 2 CPU、4 GiB、120 秒执行，查看日志并核对结果。

`bash` 回传任务 ID，模型用 `job_status` 和 `job_logs` 查询。单一工作区一次只执行一个命令任务，避免两个命令同时修改项目；不同工作区按服务总预算并行。CPU、内存或 GPU 不足会返回明确容量错误。

长程式应明确指定 `timeout`，默认 600 秒，最大 86400 秒。没有日志输出不会触发超时，关闭工作台也不会取消已开始的远端任务。需要终止时指定任务 ID 使用 `job_cancel`；只有确认 runtime 清除后才释放预留。

近期日志保留 16 MiB，超量时轮替，不因日志量杀掉计算。`job_logs` 返回 byte cursor 和 `truncated`，可增量读取。需要永久保留的完整日志由程式写到 `/output`。

## 上传、下载与资料版本

`/upload` 由操作人员选择本机文件与远端相对路径，按 1 MiB 分块上传，逐块与整档核对 SHA-256。中断后重跑相同文件／目标，使用既有上传 ID 接续；完成后移除中转内容，只保留小型收据。

`/download` 指定任务 ID、产物相对路径及本机储存位置。下载先写 `.partial`，校验完成才更名；任务执行中也可下载已落盘文件。若文件在读取期间改变，返回 `artifact_changed`，应先让程式产生稳定快照。下载不会覆盖成未校验的半个文件。

模型可用 `dataset_publish` 把远端项目资料夹发布成新的只读资料 ID。后续 `bash` 的 `datasets` 参数指定这些 ID，即可从 `/data/shared/<id>` 读取。修改项目不会改变已发布版本；更新时再发布。这些版本在同一个 worker 内共用，跨服务器同步需由操作人员额外安排。

每次上传／每个资料版本上限为 100 GiB；每个版本最多 10,000 个文件。这不是全磁碟硬配额，部署时应给服务独立的资料磁碟或文件系统 quota。

## 连线恢复

- 订阅过期：`/network` 更新订阅，再「启动／套用出口」。
- SSH 主机密钥变更：在操作端核实实例，重新 `/verify-server`，不跳过主机验证。
- 服务器重启／SSH 隧道中断：确认 `/status` 后重新 `/tunnel`。断线期间外网保持封闭。
- 返回 `remote_outcome_unknown`：先查询任务或文件，避免盲目重送有副作用的命令。
- `controller_interrupted`：控制程序确实消失；服务只回收该任务的 runtime。这和工作台断线、程式暂时不输出日志不同。
